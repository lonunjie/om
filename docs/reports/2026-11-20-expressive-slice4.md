## Implementation

The `expressiveMedia` PlatformAdapter family is unavailable by default. An explicitly enabled adapter imports the driver at first use. The driver accepts the plaintext and aggregate header facts produced together by Core's [expressive WebP walker](../../crates/om-core/src/expressive/webp.rs). It checks the frozen per-kind resource profile and `om.expressive.budget-v1` before copying bytes or creating a worker. Its preflight includes both canvas axes, frame count, per-frame and total pixel limits, encoded size, duration and the multiplication bound.

The dedicated worker uses `ImageDecoder` for supported animation and `createImageBitmap` for a static image or representative frame. It compares native dimensions and, when exposed, track frame count with Core's validated facts. The bitmap-only path returns an unknown observed frame count and a static frame. The adapter hands decoder observations and fallback reasons to the caller through typed PlatformAdapter results. Core retains rendering authority.

The worker returns one frame per request, closes the native frame after RGBA readback, and transfers that readback to the consumer. The consumer owns frame pacing and replaces the previous frame. Reduced Motion keeps the first frame visible until explicit play. Pause suppresses publication of an in-flight frame, and disposal terminates the worker. The watchdog deducts active request time from one five-second budget for the session. Failure, disagreement or timeout resolves to a fallback result. Worker startup requires the same-origin bundled asset and a Trusted Types policy pinned to its URL.

## Open integration and evidence

- Which Core binding should hand off `Opened::Renderable` and consume the decode observations? [Core returns validated plaintext and facts](../../crates/om-core/src/expressive/asset.rs) in Rust. The current web binding exposes the generic attachment path. The reference app stays on its default-off configuration pending the typed handoff.
- Which browser measurement will validate ADR-0251's 64 MiB resident ceiling, including native decoder and graphics allocations? At the largest canvas, the adapter accounts for four RGBA surfaces at 16 MiB and streams one output at a time. Browser-native cache and allocation peaks require the supported-browser matrix. The Node tests establish that rejected facts create zero workers and zero decoder allocations.
- The native browser playback and timeout matrix and V-012 release evidence remain open. A browser with worker bitmap decoding and without animated WebP decoding can display a static representative frame. A browser without a usable worker decode path uses the inert fallback. [HTML ImageBitmap](https://html.spec.whatwg.org/multipage/imagebitmap-and-animations.html#imagebitmap) · [WebCodecs ImageDecoder](https://www.w3.org/TR/webcodecs/#imagedecoder-interface)
