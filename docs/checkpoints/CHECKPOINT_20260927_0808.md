- **Decision:** ADR-0140 pulls the former later AsyncKeyBundle privacy design into v1. Provider-visible `acs_generation`/`acs_state_hash` are removed; numeric keys 3/4 are retired/reserved and rejected. Fetchers validate DeviceCredential authority against relationship-pinned peer ACS instead of provider-visible account state metadata.
- **Rollback rule:** signed-prekey `generation` is globally monotonic per `(DeviceID, CryptoProfile)` across provider pools. Recipients persist `(highest_generation, generation_core_hash)` per peer AccountID + DeviceID + CryptoProfile; lower generations are rejected and equal-generation/different-core bundles are equivocation. `provider_pool_id` never creates a new freshness namespace.
- **One-time prekeys:** the device signature input now binds version, subject DeviceID, CryptoProfile, bundle generation, provider pool, kind, key id and public key. Cross-device/profile/generation/pool transplantation therefore changes the signed preimage and fails validation.
- **Compromise/restore:** rotation uses fresh EC/PQ signed-prekey secrets and fresh key IDs at a strictly higher generation; old-generation one-time material is retired. Provider generation deletion is best-effort cleanup only. Private multi-device/backup freshness merges monotonically; equal-generation/different-core merge is a security conflict. If all copies of a newer observation are lost, the first-observation limitation is stated explicitly rather than replaced with provider trust.
