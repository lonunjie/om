The pass found a real crash-consistency ambiguity in ADR-0142: a receiver could durably reserve `(delivery_key_id, delivery_id)`, crash before inner durable acceptance, then treat the exact retransmission as a terminal replay. That turns the required replay barrier into a message-loss path.

ADR-0143 fixes this without changing the wire format or primitive:

- local replay records bind an exact-wrapper fingerprint and have `RESERVED`, `COMPLETE`, or `REJECTED` state;
- only the exact same wrapper may resume an interrupted `RESERVED` attempt;
- same key/id with different wrapper bytes is rejected;
- inner K2 session/dedupe acceptance and `COMPLETE` commit in one crash-consistent transaction/equivalent before app-visible release/ack;
- `COMPLETE` retries are idempotent and never repeat inner effects; and
- route migration still requires route-specific keying, fresh HPKE randomness and a fresh `delivery_id`.
