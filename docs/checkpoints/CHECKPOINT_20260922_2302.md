Architecture may be prototyped, modeled, fuzzed, researched, and adversarially tested where necessary to establish feasibility, but no product implementation program begins until the architecture-freeze questions are resolved or deliberately bounded by an accepted ADR.

## Constitutional direction

OM is intended as a gift to humanity, stewarded initially under SeedLife / `lonunjie` but not owned in the protocol sense by SeedLife, the founder, a company, a hosting provider, or any future governance body. Users are the principals; infrastructure and institutions are replaceable tools.

The canonical philosophy is `PROJECT_PHILOSOPHY_AND_ANTI_CAPTURE.md`. Its operational implications are machine-enforced by `machine/repository_contract.json`, `machine/architecture_map.json`, `machine/file_registry.json`, the machine decision/requirement/question ledgers, and `tools/validate_architecture.py`.

Commercial participation is permitted and welcome. Anti-capture is not anti-business. The design prevents control by ensuring that no business needs permission to implement the protocol, no proprietary service is mandatory, canonical compatibility is testable, users can move providers, and the community retains durable rights and a practical fork path if stewardship is captured.

## Licensing decision

The project uses licenses according to the role of each artifact rather than forcing one license onto incompatible goals:

- Shared portable core/client/security libraries: **MPL-2.0**. Changes to covered files remain open when distributed while independent surrounding applications can use the library without whole-application copyleft.
- Canonical OM reference network services/providers/provisioning components: **AGPL-3.0-or-later**. Modified hosted versions must make corresponding source available to their network users. Independent compatible services may be written from the protocol specification under other licenses.
- Normative protocol schemas, registries, conformance interfaces, test vectors, and interoperability artifacts: **Apache-2.0**. The protocol itself must remain broadly implementable, including by independent and commercial implementations.
- Architecture, governance, research, and explanatory documentation: **CC-BY-SA-4.0**.

Contributors retain their copyright. Ordinary contributions use DCO sign-off and inbound-equals-outbound licensing; the project does not require a broad copyright-assignment/relicensing CLA that could later create a proprietary capture point. Before broad external protocol contribution begins, OM will adopt lawyer-reviewed royalty-free patent/disclosure language so mandatory protocol mechanisms cannot knowingly become royalty- or permission-gated.

## Stewardship and continuity

This checkpoint deliberately accepts a **single-founder incubation stage (S0)**. OM will not manufacture fake redundancy by giving authority to people merely to satisfy a governance diagram.

The repository nevertheless defines the rails for later continuity now: organization owners, OM maintainers, security responders, protocol editors, release managers, release-root custodians, domain/DNS custodians, and distribution custodians are distinct roles. They can be populated incrementally when trustworthy people exist. Project-governance changes never alter end-user `AccountID` or grant protocol authority.

Before public-production maturity, the target is multiple organization owners, multi-party release-root custody, redundant control of essential domains/registries/distribution assets, multiple security contacts, and a creator-disappearance drill. These are maturity gates, not requirements to appoint untrusted people today.

## Architecture gaps promoted to first-class design work

This checkpoint adds explicit architecture for asynchronous key material, one-to-one multi-device session management, MLS same-epoch Commit ordering and OM group-state binding, catastrophic reachability and blob-location repair, canonical time/expiry semantics, and the self-hosted ClientHost update lifecycle.

It also narrows browser/PWA promises to actual platform capabilities, requires SSRF-safe link-preview infrastructure, treats provider failure-domain declarations as hints rather than proof, and retains the production-crypto integration gate.
