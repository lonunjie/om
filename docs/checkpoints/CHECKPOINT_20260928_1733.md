## Normative hardening

- **Presentation extensions / V-005:** `om.voice-note.v1` and `om.location-card.v1` are now canonical registered key-23 extensions rather than prose-only IDs. Registration binds owning object (`ConversationEvent`), exact non-critical bit and schema. Their payloads are integer-keyed registered structs. The location point uses unsigned E7 offsets to stay inside the frozen generic registry grammar. A location fallback must contain the exact canonical `geo:<lat-fixed-7>,<lon-fixed-7>` token for the decoded point; a mismatch causes only the non-critical card interpretation to be ignored so old/new clients cannot show different authenticated points.
- **Account-private sync / V-003:** records now have mandatory abstract causal semantics: profile + origin DeviceID + origin ACS generation + durable origin sequence + stable item/type/version/operation + causal context. Provider arrival order/HLC is not authority. Remote HLC more than the frozen 300-second future skew is quarantined. Tombstones beat concurrent stale writes; post-delete recreation must causally descend from the tombstone; draft resolution binds every superseded head. Historical backup restore creates a fresh DeviceID and imported old draft/preference material is not automatically republished before current sync reconciliation.
- **Profile switching / V-021:** profile-sensitive work captures immutable `ProfileExecutionContext` at dispatch. Attachment/media/file-picker/search/share/deep-link/notification/background-sync and independent-window callbacks cannot consult a later process-global active profile. Switching A→B therefore cannot retarget an in-flight A result into B. Clipboard is explicitly an OS-global disclosure boundary, not a profile-private namespace.
- **Update signatures / V-023:** algorithm agility is now explicitly authority-bound. Thresholds count distinct authorized role/key IDs under the current owner-pinned root policy over exact canonical metadata bytes; right-algorithm/wrong-key, wrong-role, duplicate-key counting, key-ID algorithm/public-key substitution and role/version substitution fail closed. Root-policy rotation is sequential and requires both the previously trusted root threshold and the new root's own threshold.
