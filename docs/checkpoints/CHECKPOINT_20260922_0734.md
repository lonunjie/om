# Architecture Checkpoint — 2026-09-22 07:34 PHT

## Theme

**Operatorless core, coherent client family, optional convenience economy.**

This checkpoint answers a fundamental product/governance question: OM does not need a company behind the network, but it also does not need to remain PWA-only or reject future businesses.

## Frozen directions

### 1. No mandatory OM operator

The protocol/core must work without an OM-operated relay fleet, directory, account database, push gateway, recovery provider or abuse desk.

### 2. PWA-first, not PWA-only

The first reference distribution should prove operatorless deployment and ordinary messaging through an installable PWA. Native shells remain planned for platform capabilities that the web cannot fully replace.

### 3. One portable OM Core

Identity, cryptography integration, AccountControlState, event semantics, discovery, sync, recovery and canonical encodings should live in one shared memory-safe core (Rust is the current preferred direction) compiled to WASM/native targets.

### 4. Distribution-local infrastructure

A native App Store/Play build may need its own push gateway, store compliance/reporting process and signing/update channel. Those belong to that distribution, not OM protocol semantics.

### 5. Operatorless provisioning

Cloudflare Deploy-to-Cloudflare/public templates are preferred where they can create resources directly in the user's own account. OAuth automation remains optional.

### 6. Local abuse response

Core flow is Block + selective EvidencePackage export. The project need not receive reports. A managed provider/store distributor can add a ReportTarget when required.

### 7. Convenience economy

Future commercial providers may offer managed hosting, media, directories, support or enterprise tooling. They have no protocol privilege and must support migration/portability.

### 8. Creator-Disappearance Gate

If the original author/project/business disappears, existing independent users continue communicating and other maintainers can continue implementation from mirrored source/spec/test vectors.

## Security consequences

- client distribution/update trust remains a first-class security boundary;
- web code-delivery risk remains distinct from native signed-binary risk;
- PWA Web Push avoids a universal project push gateway but still traverses browser/platform push infrastructure;
- native clients can offer stronger platform key custody and background/calling integration;
- protocol capability negotiation must never encode “official client” privilege.

## Legal consequences

Architecture minimizes centralized custody but does not promise zero obligations. Responsibilities attach to the role actually performed. Jurisdiction-specific obligations remain role-specific pre-launch gates for any project-controlled distribution or hosted service. App-store distributions may inherit store moderation/reporting obligations that the operatorless PWA/core does not make universal.
