# OM Engineering Checkpoint — 2026-09-22 14:34 PHT

## Focus

Close remaining expensive-to-retrofit design gaps and hand the complete architecture to a coding agent for engineering.

## Canonical additions

1. `ClientHost`, `DeviceVault`, `IdentityProfile` and `IdentityHome` are distinct layers.
2. PWA origin/provider migration is authenticated device transfer; browser database copying is not an identity protocol.
3. Multi-identity isolation is built into v1 core/storage; visible multi-account switching may ship later.
4. Profile switcher is intended to be instant/simple; optional distinct curated theme per profile.
5. Every theme has light+dark variants; Auto follows system appearance.
6. RichTextV1 is a bounded semantic tree providing Telegram-class formatting without HTML/active markup.
7. Decrypted content remains hostile; attachment/link/clipboard/theme parsing gets explicit limits and fuzzing.
8. Ordinary messages remain secure-session authenticated rather than gaining separate durable AccountID signatures; durable control objects stay signed.
9. LocalDataClass defines deletion/cache/backup lifecycle and diagnostics are local-first/redacted.
10. Canonical signed/wire encoding direction is deterministic CBOR based on RFC 8949 with tighter OM constraints.
11. AccountControlState TLA+ modeling is an engineering gate.
12. Production cryptography is a dedicated integration gate; dev crypto may unblock prototypes but cannot ship as secure.
13. Security/crypto references were re-audited against current NIST, Signal, IETF MLS, OpenMLS, W3C, TUF/SLSA/in-toto, OWASP and Unicode material.
