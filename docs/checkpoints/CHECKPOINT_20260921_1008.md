# Architecture Checkpoint — 2026-09-21 10:08 PHT

This checkpoint expands OM discovery from a simple directory/alias model into a full **Discovery Fabric** and extends relay/network resilience.

## Decisions added

1. No mandatory global username registry or blockchain root.
2. Add a client-side OM Resolver; every discovery mechanism yields a validated `ContactDescriptor`.
3. Learn from DNS: delegation, caching/TTL, resolver/authority separation, multiple endpoints, local resolution; do not copy its single global root or plaintext privacy model.
4. Support optional oblivious directory lookup so no one provider necessarily learns both requester IP and queried alias.
5. Public directory records expose `IntroductionServiceDescriptor`, not reusable mailbox/invite secrets.
6. Add revocable invites with expiry/use-count/scope and explicit offline-revocation limitations.
7. Add short-lived/single-use `IntroductionTicket` and `IntroGate` admission control for first-contact spam/DDoS.
8. Make multiple simultaneous relays a first-class `RelaySet`; use distinct capabilities and independently randomized envelopes per relay.
9. Add privacy-preserving rotating LAN rendezvous and offline-local operation direction.
10. Design for state-level censorship resilience through provider/transport diversity and pluggable transports, while explicitly avoiding impossible uncensorability claims.

## Product invariant

Ordinary users still experience only:

```text
Search → tap
Scan QR → tap Connect
Send message / call
```

The resolver, tickets, relay selection, caching, provider diversity, revocation, and transport adaptation remain invisible by default.
