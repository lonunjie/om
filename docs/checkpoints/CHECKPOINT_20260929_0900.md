# Checkpoint — 2026-09-29 — Run 6 dangerous-algorithm hardening

## Scope

Pre-engineering implementation-readiness hardening after Run 5. No product implementation and no external/human verification closure.

## Findings fixed

1. Authorization dependencies, integration prerequisites and practical implementation order were scattered across handoff prose. `machine/engineering_scope_contracts.json` now covers all 12 scopes and mirrors `repository_contract.json` authorization dependencies exactly while keeping integration prerequisites separate.
2. Crash/restart and lost-response handling lacked one canonical cross-scope transaction rule. ADR-0163 now requires stable logical-operation identity where uncertainty can cross an external effect, treats post-send timeout/disconnect as an unknown outcome, and requires durable commit before irreversible local release/success acknowledgement.
3. Group Commit crash/retry behavior was still a checklist. It now uses a durable staged journal (`INTENT_DURABLE`, `CANDIDATE_PREPARED`, `PUBLISHED_UNCONFIRMED`, `ACCEPTED`, with terminal `SUPERSEDED`/`ABANDONED`), exact prepared MLS Commit persistence, tentative-branch isolation and canonical-state reconciliation. V-004 remains open for formal/runtime/wire/independent evidence.
4. Provider `request_id` idempotency did not explicitly require survival across provider restart. It now does for the advertised retry horizon, with same-ID/different-operation reuse rejected.
5. Core/UI outcomes did not distinguish ordinary pending-network state from an externally visible mutation whose outcome is unknown. `PendingReconciliation` now covers that boundary and restart reconstruction cannot silently convert uncertainty into rejection or a second semantic operation.
6. Engineering handoff material still mixed direct unlock gates with cross-wave feasibility constraints and contained stale scope presentation. The 12-scope gate/dependency presentation and implementation layering are now explicit.
