# UI/UX Validation Gates

**Status:** normative pre-freeze gates for the default OM experience.

A design is not accepted merely because it matches a mockup. The default shell and theme must pass functional, ergonomic, accessibility, performance, and comprehension gates.

## Gate VUX-01 — Meaning survives without color

Required:

- grayscale inspection leaves unread, focus, selection, warning, failure, verified, and destructive actions understandable;
- every important color-coded state has text/icon/geometry/position redundancy.

Rationale: WCAG 2.2 SC 1.4.1 prohibits color as the sole visual means of conveying required information.

## Gate VUX-02 — Text and UI contrast

Required for default/preset themes:

- normal text >=4.5:1 in ordinary use;
- large text >=3:1 where WCAG large-text criteria apply;
- necessary UI boundaries/state indicators >=3:1 against adjacent colors;
- custom focus indicator remains strongly visible in both light and dark modes.

OM intentionally targets comfortable margin above minimums for frequent chat text.

## Gate VUX-03 — Targetability

Required:

- high-frequency compact-mobile OM-owned controls target ~48 px preferred;
- 44 px lower normal bound unless an equivalent large target/hit area exists;
- controls do not visually overlap or create high-risk adjacent taps;
- one-handed tests cover both hands and multiple device widths.

WCAG 2.2 AA target-size minimum is a floor, not OM's ergonomic goal.

## Gate VUX-04 — Large text and reflow

Required:

- text scales to at least 200% without loss of content/functionality;
- chat rows can grow vertically rather than truncate essential status/action text;
- composer/Omnibar remain usable under large text;
- no fixed-height component clips required labels.

## Gate VUX-05 — Keyboard-only completion

Required desktop/tablet/PWA tasks without pointer:

- open conversation;
- search/find with Omnibar;
- compose/send;
- reply;
- open/close menu or sheet;
- reach settings;
- return/back;
- activate invite actions.

Focus is always visible and not obscured by the lower shell or overlays.

## Gate VUX-06 — Concurrent input

The interface must not lock the user into touch, mouse, keyboard, voice, or other supported modality after one is used. Switching modality mid-task must preserve state and focus logically.

## Gate VUX-07 — Reduced motion

With Reduce Motion enabled:

- semantic meaning survives;
- spatial transitions may become fades/instant state changes;
- repetitive, zooming, bouncing, and peripheral decorative motion is suppressed;
- OhMessenger delight never becomes necessary to understand state.

## Gate VUX-08 — Light/dark semantic parity

Light and dark pairs must preserve:

- action hierarchy;
- focus visibility;
- warning/danger/success differentiation;
- incoming/outgoing distinction;
- readable metadata;
- equivalent information hierarchy.

Dark mode is tuned independently, not generated by inversion.

## Gate VUX-09 — Error/recovery comprehension

Users should be able to distinguish queued/pending from failed and know the next safe action. Failure should remain attached to the affected object; avoid generic detached error dialogs when object-local recovery is possible.

## Gate VUX-10 — Omnibar stability and latency

Provisional prototype budgets on representative target hardware:

- keystroke echo: next frame / no perceptible blocking;
- hot suggestions: <=50 ms p95;
- people/actions: <=75 ms p95;
- first warm local message batch: <=150 ms p95;
- no selection-jumping from late asynchronous ranking updates.

These are engineering targets to benchmark, not claims already proven by this design package.

## Gate VUX-11 — First-run comprehension

Without onboarding slides, a zero-contact user can identify a useful next action: invite, scan QR, or show their QR. The screen must not pressure contact upload or network-growth permissions.

## Gate VUX-12 — Theme safety

Every built-in preset and installable theme must pass the protected Theme Contract. A theme cannot:

- alter action semantics;
- weaken destructive-state cues;
- hide focus;
- shrink protected hit targets;
- eliminate required contrast;
- turn status colors into ambiguous decoration;
- force motion that ignores Reduce Motion.

## Gate VUX-13 — Human validation

Automated checks are necessary but insufficient. Before brand/default freeze, run structured tasks with real users covering:

- ordinary mobile messaging users;
- keyboard-heavy desktop users;
- at least some users with accessibility needs when recruitment is practical;
- different hand sizes / left- and right-handed use;
- representative low- and mid-range devices.

Record completion, errors, recovery, hesitation points, and subjective workload. Do not declare a default "proven" from screenshots or simulations alone.
