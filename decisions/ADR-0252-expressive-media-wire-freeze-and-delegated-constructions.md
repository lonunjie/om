# ADR-0252 — Expressive-media wire freeze (W1) and the constructions the design leaves to engineering

- **Status:** Accepted by delegation (2026-11-20), additive, accepted-gated for the wire it freezes. It amends no audited text and weakens no cryptographic floor: it fills two slots that W0 already reserves, adds two object types, one non-critical extension, one registry file and four labels.
- **Date:** 2026-11-20
- **Scope:** engineering scope `expressive_media` (ADR-0250), slice 0 of [`2026-11-20-expressive-media-build-plan.md`](../docs/reports/2026-11-20-expressive-media-build-plan.md). Budgets are those of ADR-0251.
- **Class:** `additive_noncritical_extension` (ADR-0165). No W0 object, label, enum value, key or frozen corpus changes; the frozen W0 vector corpus regenerates byte for byte under the edited registries.
- **Answers:** plan questions Q4, Q5 and Q6.
- **Evidence:** [`expressive.cddl`](../spec/cddl/expressive.cddl); [`om-expressive-media.json`](../spec/registries/om-expressive-media.json), [`om-w1-expressive-slots.json`](../spec/registries/om-w1-expressive-slots.json) and rows in [`om-numeric-fields.json`](../spec/registries/om-numeric-fields.json), [`om-object-types.json`](../spec/registries/om-object-types.json), [`om-domain-separation.json`](../spec/registries/om-domain-separation.json), [`om-cbor-profile.json`](../spec/registries/om-cbor-profile.json); [`expressive-wire-vectors.json.gz`](../verification/vectors/expressive-wire-vectors.json.gz) (positive and negative object, struct, claims, container-budget, lineage, pack-ref and emission-gate cases); [`expressive-wire`](../verification/prototypes/expressive-wire/run.sh) (Python generator and checker, two strict prototype codecs, two CDDL tools) and the product codec test `crates/om-codec/tests/expressive_vectors.rs`.

## Design sources read

The expressive-media, content-pack and entitlement architecture note, ADR-0128 rules 17 and 18, ADR-0129 rule 10, ADR-0155, ADR-0165, ADR-0176 (the freeze method), ADR-0189 (precedent for `required_capabilities`), ADR-0250, ADR-0251, the calls freeze ADR-0218 (method), and the constitution digest.

## Decision

1. **`ExpressiveAssetRef`** is the W0 attachment-ref (keys 0 to 10, unchanged meaning) plus `kind` 11 (sticker 1, custom_emoji 2, reaction_asset 3, loop_animation 4), `media_profile_id` 12, `alt_text` 13, `fallback_text` 14, `pack_ref` 15 and `shared_blob` 16 (`true` only). Width, height and `plaintext_size` are required and non-zero. A `media_profile_id` the receiver does not know is valid and renders as a placeholder with its fallback; it is never an event failure.
2. **Slots.** `ReactionSet` key 3 (`reaction_asset`) and `RichText` inline type 4 (`InlineCustomEmoji`: type, `fallback_text`, asset in key 6) are the two W0-reserved slots, filled through the overlay file in the ADR-0176 manner. A W0 decoder keeps rejecting both. A custom reaction keeps `present` true and uses the existing key-1 text token as its fallback text token (the design is silent on a canonical token; see the residuals).
3. **Non-critical extension `om.expressive.asset.v1`** (event key 23, `message.create` only) names an attachment by index and states `kind`, `media_profile_id`, `alt_text`, `fallback_text` and `pack_ref`, so an ordinary W0 message with an `image/webp` attachment carries the expressive meaning for a W1 receiver. A schema or claim failure in it is ignored and never fails the event (ADR-0155).
4. **Profiles and budgets.** Media profile `om.expressive.webp-v1`; resource profiles `sticker.v1`, `custom-emoji.v1`, `loop-animation.v1` bind to the kinds; the header-only claims validator and the container-fact budget `om.expressive.budget-v1` are those of ADR-0251, with `4294967295` as the multiplication limit (an overflow is a reject). Text limits are in Unicode scalar values (alt text 512, fallback 128, item id 128, title 256, description 4096, label 512, keyword 64, emoji association 32).
5. **Q4: capability advertisement.** Three registry capability IDs: `om.expressive.webp-v1` (renders the media profile), `om.expressive.inline-emoji.v1` (inline type 4) and `om.expressive.reaction-asset.v1` (reaction key 3). A device advertises them in the capability set it already carries in its signed device credential; an event that uses a slot carries the slot capability in its existing `required_capabilities` list (key 10), so a receiver without the capability treats the slot as W0 does. **Emission gate (ADR-0128 rule 18):** a sender emits a slot or a profile only when every recipient device advertises both the slot capability and the media profile; with no known recipient device, or any device lacking either, it sends the W0-valid fallback (a plain attachment and text). The gate is a vector table.
6. **Q5: signed bytes.** `ContentPackRelease` (type 45) is **unsigned** and immutable; `ContentPackReleaseID` is `DS-HASH` under `OM-CONTENT-PACK-RELEASE-HASH-v1` of its canonical bytes. Authenticity comes from `ContentPackControlState` (type 46), a hash-chained SignedEnvelope signed under `DS-SIG` with `OM-CONTENT-PACK-CONTROL-SIG-v1`, signature role `controller`, chained by `OM-CONTENT-PACK-CONTROL-HASH-v1` over the previous state. A `PackController` is `{key_id, crypto_profile, public_key}` with `key_id` the first 16 bytes of the `DS-HASH` digest (`OM-CONTENT-PACK-CONTROLLER-KEY-ID-v1`) of the OM-CBOR array `[crypto_profile, public_key]`. The signature set is distinct controllers of the **previous** state (of this state at genesis), at least `threshold` of them, never more than the controller count; the threshold is part of the signed body. No new primitive: the existing signature profiles and envelope are used. Specialist cryptographic review of this threshold construction stays a release obligation (as ADR-0217 point 4 does for calls).
7. **Q6: pack attribution.** `ExpressivePackRef` is `{pack_id: 32 bytes, release_id: digest, item_id: text 1 to 128 scalar values}`. A pack ref is claimed attribution, never a rendering dependency. A receiver shows pack attribution only when it holds the release and the named item matches the asset on identity fields (**attributed**); otherwise (release unknown, item absent, or any field differing) the asset renders from its own blob with **no** pack name or provenance claim (**unattributed**). Attribution is never fetched from a catalog.
8. **Lineage.** `release_sequence` is 1 exactly when `previous_release_id` is absent; a fork (`forked_from`) only at sequence 1. A control state's `release_sequence` equals the previous or previous plus one, equal exactly when `release_id` is unchanged. A release in an update chain keeps `pack_id`; a changed `pack_id` is a different pack.
9. **Release content rules.** Items unique by `item_id`, item kind equals the asset kind, and an item asset carries no `locations`, `repair_capability`, `pack_ref` or `shared_blob`: a release names its bytes by digest only, so a manifest carries no delivery capability and no account identifier. No field introduced here carries an AccountID, DeviceID or delivery capability. There is **no time field** and keys 12 to 22 of a release and 9 to 22 of a control state are held.
10. **Bounds.** Release object 2,097,152 bytes (at most 512 items); control state 131,072 bytes (at most 16 controllers).

## Where did authority go?

Nowhere new. A pack controller set authorizes pack lineage only, never conversation rendering, identity or delivery; the sender's own asset is what a message renders; capabilities are advertised per device and decide only what a sender may emit.

## Residuals (no wire effect, recorded for slices 1 to 3)

- The canonical token for a custom reaction is not fixed by the design; v1 keeps it free text within the existing 64-byte reaction key.
- A genesis control state is trusted on first sight; pinning that first state is a client policy (slice 5).
- Changing a device's advertised capabilities needs the existing device-credential re-issue; how a Room sender obtains each member device's credential is left to slice 2.

## Consequences

Slice 1 builds the header walker and budget validator against `om.expressive.budget-v1`; slice 2 decodes through `om-codec` with the overlay promoted only by a later ADR. Engineers never invent fields.
