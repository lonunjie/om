## Context

D114 shipped the same-name cues with exact equality after NFKC, case folding and trimming, and left lookalike matching open: "Maria" with a Cyrillic "a" is a different string and showed no cue. IS-01 asks for current UTS #39 confusable and mixed-script mechanisms and "calm warnings only when the identifier meaningfully resembles another". The open questions were where the matcher lives, where its data comes from, and how it stays calm.

## Decision

1. **The matcher lives in the client (`om-ui`, `groups/lookalike.ts`), not in Core.** The result is a display cue; Core has no use for it and its state, views, backup and wire are unchanged. The groups wasm module is already at 96 percent of its ADR-0187 delta limit ([`apps/web/build/size-budget.json`](../apps/web/build/size-budget.json)), so a Core table would have to be paid for from a budget that has about 82 KB raw and 28 KB gzip left; a client table costs about 2.4 KB of source and the budget check does not move (measured in the report, relay status D135). The web JavaScript bundle has no size budget file.
2. **Rule.** Two shown names collide when (a) they are equal after NFKC, case folding and trimming (unchanged, kind `same`), or (b) they differ but have the same lookalike key (kind `alike`). The lookalike key is: NFKC; drop invisible default-ignorable code points (zero-width space, word joiner, soft hyphen, bidi controls, variation selectors, combining grapheme joiner; a ZWJ or ZWNJ is dropped when either neighbour is a letter or digit of Latin, Cyrillic, Greek or Armenian and kept otherwise, so emoji, Arabic and Indic sequences keep their joiners); NFD; map each character through the pinned table; NFD; collapse white space; fold case. The skeleton is taken before case folding so that capital I, lowercase l and 1 meet (the table maps them to l). Combining marks are not stripped: "Jose" and "José" are different names. Only the first 256 code points are looked at.
3. **Mixed-script detection is a classifier, not a trigger.** A name is mixed-script when its letters fall in two or more of Latin, Cyrillic, Greek and Armenian. IS-01's "calm warnings only when the identifier meaningfully resembles another" means a mixed-script name alone (for example a Latin name with a Russian surname) produces no cue; a mixed-script name that has the skeleton of another name is rule (b) already. `isMixedScript` is exported and tested, and used by nothing else; it is there for a later contact detail or first-contact screen (D137).
4. **Data: a pinned, minimal extract of Unicode `confusables.txt`.** `packages/om-ui/data/confusables-extract.txt` holds the source's header and 209 unchanged source lines: a one-character source that is ASCII or in a block of Latin, Cyrillic, Greek or Armenian, is unchanged by NFKC then NFD (so it can actually occur), and has a prototype of ASCII letters and digits only. CJK, Arabic, Devanagari, Hebrew, Thai, emoji and punctuation sources are therefore outside the table and can never make a name look like another. The file records the Unicode Security Mechanisms version (18.0.0, dated 2026-08-06) and the SHA-256 of the full source file (`6ed3ee96...f5b92`). It was downloaded once from `https://www.unicode.org/Public/security/latest/confusables.txt` (no versioned 18.0.0 directory existed on the server that day) and is under the Unicode License v3 (`LICENSES/Unicode-3.0.txt`, REUSE annotation). [`apps/web/build/gen-confusables.mjs`](../apps/web/build/gen-confusables.mjs) (`extract <file>`, `generate`, `check`) writes the extract and `confusables.generated.ts` (code points as hex, so no lookalike character sits in the source); `apps/web/build/gen-confusables.test.ts` regenerates the table from the checked-in extract and compares it with the checked-in file, checks the recorded hashes and the filter. Nothing is fetched at build or run time. Refreshing the data is a deliberate act: download, run `extract`, review the diff, commit.
5. **Scripts are blocks, not Script_Extensions data.** Latin, Greek, Cyrillic and Armenian letters are told apart by listed Unicode blocks (also emitted by the generator), so the answer does not depend on the Unicode version of the browser or Node. This is a subset and an approximation of Script_Extensions (D136).
6. **Bounds against false positives.** A skeleton of fewer than two code points never matches as a lookalike (an equal name still collides, as before). Distinct names in any other script, emoji names and names that differ in an accent do not match (the corpus in `lookalike.test.ts`). Names made only of invisible characters never match. Work per name is bounded (256 code points) and the grouping is linear in the number of people.
7. **Cue and wording.** The cues are the D114 ones, unchanged in shape: the pattern, "Name (1 of 2)" and one non-modal line, in the people sheet, the room, the add list, the new-group pick list and an incoming invitation. One new copy key, `sameName.alike(name, count)`: "N people here have names that look similar to X. A name does not show who someone is." A group in which every name is the same after normalizing keeps the D114 line ("are named"); a group in which any two differ uses the new line. The wording says "look similar", never fake, never suspicious, never a warning; nothing is blocked, hidden or confirmed. The comparison is made on the shown name (nickname else display name, ADR-0196), so a nickname ends a collision.
8. **Failure.** The matcher is a pure function on strings that cannot fail; a wrong "alike" costs one calm line and a pattern, a miss leaves today's behaviour. No name is ever treated as identity (IS-01), and the account and its independent verification path are untouched (IS-02, D129 stays open).

## Where did authority go?

Nowhere. The key is computed from a name on the device that shows it, is never stored or sent, and decides nothing but whether a line and a pattern are shown.

## Not done, and why

- No cue at first-contact and discovery surfaces (message requests, introductions, search results, the Omnibar) and none in the 1:1 conversation list: those screens do not compare a name with the person's other contacts today. IS-01 names those surfaces, so this is a departure (D138).
- No full UTS #39 data (D135) and no Script_Extensions data (D136); no "restriction level" or "highly restrictive" verdict (D137).
- No canonical-detail or AccountID reveal (D129).
- Lookalikes outside the table (for example Cherokee, Coptic, Georgian, Hebrew letters that resemble Latin) are not matched.

## Consequences

- "Maria" with a Cyrillic "a", an "I" for an "l", an "rn" for an "m" or a zero-width character inside a name now draws the same pattern, "(1 of 2)" and a calm line as an exact duplicate.
- Real different names can collide (for example "Tom" and "Torn", "Al" and "AI"): one calm line, nothing blocked.
- The table is 209 pairs and does not grow with Unicode until someone refreshes it on purpose.
