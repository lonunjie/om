# ADR-0259 — Authorize engineering scope `plugins` (W4), by explicit operator instruction

- **Status:** **Accepted** (operator, 2026-11-23, explicit instruction in chat; not delegation). Authorizing an engineering scope is a decision of the operator, not a review result and not a delegation. The operator's instruction was conditional: authorize each remaining scope that is part of the design and aligns with the constitution. This ADR records that check for this scope.
- **Date:** 2026-11-23
- **Authorizes:** engineering scope `plugins` only. No other scope changes state through this ADR.
- **Depends on:** the scopes named in `depends_on` for `plugins` in the repository contract, already authorized.
- **Waives:** the **pre-engineering** phase of gate V-010 for engineering purposes only. Its pre-release phase is untouched and stays open.

## Context

`plugins` (W4) is part of the complete, audited design and its scope contract exists in [`engineering_scope_contracts.json`](../machine/engineering_scope_contracts.json). Constitution check: C-46 (shared meaning is never only in plugin code) and the existing UI constraints (themes and extensions cannot suppress security UI or obtain key state). The design queue has no open blocking item for it. The unlock contract ([`RELEASE_WAVES_AND_SCOPED_ENGINEERING_UNLOCK.md`](../docs/process/RELEASE_WAVES_AND_SCOPED_ENGINEERING_UNLOCK.md) section 5) otherwise requires every gate that lists the scope to have `pre_engineering_status` passed or waived by an ADR. Gate V-010 still has criteria open: all seven pre-engineering criteria: the prototype host on a native Wasm runtime and the PWA runtime with the adversarial plugins, the plaintext-read versus egress separation tests, the per-send confirmation rule, PWA separate-registrable-domain isolation, the remote-origin mini-app test, the consent rule for continuous 1:1 egress, and the ADR-0156 wire freeze; no evidence is recorded yet, and feasibility is also open. The operator may choose to authorize engineering now and keep that evidence as a release obligation. This is the same shape as ADR-0250, ADR-0217 and ADR-0183.

## Decision

1. **`plugins` is authorized**, by explicit operator instruction. Engineers follow [`ENGINEER_START_HERE.md`](../docs/process/ENGINEER_START_HERE.md), the `plugins` entry of [`engineering_scope_contracts.json`](../machine/engineering_scope_contracts.json) and the design gate in [`AGENTS.md`](../AGENTS.md).
2. **What the scope covers.** the Wasm Component-Model plugin host: plugin package manifest, capability grants and plugin-to-host message formats, the sandbox, budgets and permission prompts, and the PWA site-isolation arrangement. Sources: [`PLUGIN_AND_APP_EXTENSION_ARCHITECTURE.md`](../docs/architecture/ecosystem/PLUGIN_AND_APP_EXTENSION_ARCHITECTURE.md), [`CLIENT_AND_EXTENSION_ARCHITECTURE.md`](../docs/architecture/client/CLIENT_AND_EXTENSION_ARCHITECTURE.md).
   - **Not covered:** any plugin store or catalog hosted by the project, any plugin that changes interoperable state without a published schema (C-46), themes beyond the existing declarative-data rule. Each needs its own ADR.
3. **Gate V-010 pre-engineering is waived by this ADR, for engineering only.**
   - *Risk accepted:* this is the largest waiver of the five: the sandbox, the capability model and the wire can be written before any adversarial evidence exists, so a sandbox escape, an ambient-authority path or a plaintext-egress path could be built before the test that would have caught it.
   - *Compensating controls:* (a) the first build slice freezes this scope's wire objects (CDDL, registered numeric fields and domain-separation labels, positive and negative vectors, two independently written codecs agreeing) before any other product code, by the V-005 method, additively and under ADR-0165; (b) the feature is built behind a capability flag that is off in every release until the release evidence below is in, and no production build offers it; (c) every construction the design leaves open is written in an ADR by delegation that does not amend audited text, and where the design is silent the engineer writes the question in the scope's plan and stops; (d) no wire requirement is added to an earlier wave beyond the reserved extension and criticality points already frozen in V1 semantics (RELEASE_WAVES rule 1); (e) because no evidence exists yet, the first slice is the adversarial plugin suite and the wire freeze, and no plugin host code may be reachable in any build until that suite passes on both runtimes; (f) content-reading plugins stay disabled where site isolation is unavailable; a plugin never emits an Account-authored event without per-send user confirmation; a plugin never obtains raw protocol or key state.
4. **Still required BEFORE RELEASE, not before engineering.** external review of the sandbox host, all seven pre-engineering criteria met with evidence, and the feasibility criteria evidenced; any release offering plugins, declaring `plugins`, or claiming a sandbox guarantee needs them. `om-open-beta-1` does not list `plugins` and stays as it is. Authorization is not release: nothing here edits a public release declaration.
5. **Constraints.** No new cryptographic primitive and no weakened floor (C-20); no mandatory third-party service and no project-operated service for this scope (C-01); no design change. Where the design is silent the engineer writes the question in the scope's plan and stops, or an ADR by delegation records a construction that does not amend audited text. The first deliverable for the scope is a build plan that states which design documents were read.
6. **Where did authority go?** Nowhere new. A plugin holds only the capabilities the person grants it, and cannot act as the person without a per-send confirmation.

## Consequences

- The review basis becomes the operator's decision, not independent review. The open independence criteria of V-010 move to the release obligations in point 4.
- The first slice is design-bound specification and test work (wire freeze and the evidence harness named above); no feature code is reachable in any build until the capability flag is turned on by a later, evidenced decision.
