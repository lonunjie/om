# ADR-0191 — The Add Commit's transport frame carries the signed account heads of the added accounts

- **Status:** Accepted
- **Date:** 2026-11-16
- **Decided by:** operator delegation 2026-11-16, to fill silence and fail closed. This ADR fills silence only and amends no audited text.
- **Class:** `additive_noncritical_extension` ([`PROTOCOL_EVOLUTION_AND_CHANGE_CONTROL.md`](../docs/process/PROTOCOL_EVOLUTION_AND_CHANGE_CONTROL.md) section 2, strongest applicable class; ADR-0165). It mutates no published meaning: `GroupTransportFrame` (type 33) is W1 and unreleased (ADR-0189, 2026-11-14), and the frozen W0 corpus is unchanged.
- **Amends:** nothing. **Does not amend:** ADR-0189 (its text, including section 1.4(b), stands; this adds one optional key to the CDDL appendix object that ADR-0189 moved to [`spec/cddl/group-transport.cddl`](../spec/cddl/group-transport.cddl)), [`GROUP_CHAT_ARCHITECTURE.md`](../docs/architecture/groups/GROUP_CHAT_ARCHITECTURE.md), [`GROUP_COMMIT_AND_STATE_CONVERGENCE.md`](../docs/architecture/groups/GROUP_COMMIT_AND_STATE_CONVERGENCE.md), ADR-0128, ADR-0127, any frozen W0 object.

## Context

In a Room where two members have never met (one invites a second, then a third), the third member joins on the account heads its Welcome carries. The second member receives the Add Commit, which carries no head for the new account, so it cannot map the added devices to an account and, failing closed, holds the Commit until it expires. The Welcome already carries signed heads for this purpose (`FrameBodyWelcome` key 4); the Commit's frame does not.

## Decision

1. `frame-body-commit` gains optional key 4, `account_heads`: 1 to 64 `group-account-head` (the object the Welcome uses). The bound equals the bound on `added_devices`, which the heads can name at most. A frame without the key decodes and behaves as before.
2. A committer attaches only heads it can itself evidence (its own account's head, or a peer's head that still names the head pinned on an Active relationship), leaves out its own account, and sends the Commit without heads when they would not fit one frame (the receiver then holds, as before).
3. A receiver verifies a carried head exactly as it verifies a Welcome's (signature by a non-quarantined control device, state hash and generation, credentials the state lists). It uses one only for an account that an added device in that Commit belongs to, only when it holds no other head for the account, and stores it in the same `room_heads` store as a Welcome's, with no record of who vouched. It never replaces a held head, and refreshes through the normal head refresh. A head that cannot be verified, or names no account of an added device, is ignored and the Commit is held as before.
4. Nothing else changes: no new object, domain label, key, authority, capability or provider-visible field. The frame is still sealed per recipient (ADR-0189), so a relay learns nothing new.

## Where did authority go?

Nowhere new. A head from a Commit is evidence the receiver verifies itself and is used only where it holds none, as for the Welcome (the rule for a third account's head recorded in the relay status table, D51 and D54). The committer cannot make a receiver accept a device the account's own signed state does not list.

## Consequences

The three-person Room converges without a Welcome-only dependency. Residual: a head carried on the committer's word is a last-seen head, not proof of freshness; it is bounded as for the Welcome and refreshed once a relationship exists.
