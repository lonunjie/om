# Reader decisions and ambiguities

- The attached materials are the complete contract. The spec calls the ZIP failure class `Zip(<class>)` without defining its sub-class registry; `ZipError::class_name()` defines stable, explicit sub-classes. The locally introduced manifest-size class is `ManifestSizeLimit`. Encryption-mode `header.cbor` returns exactly `encrypted_unsupported`; ZIP flag encryption still fails the §3 container gate as `Zip(Flags)`.
- The manifest's prose says "exactly the listed keys" while marking three keys optional. The implementation demands the twelve required keys and permits only the three named optional keys. Neither unknown manifest fields nor duplicate keys are accepted.
- §3.5 permits unneeded ZIP64 end records, but ZIP64 **extra fields** remain strictly tied to `0xFFFFFFFF` sentinels as §3.1 requires. Central and local ZIP64 extra fields must have no unused or unknown bytes.
- `present=false` blobs are included in the integrity root and `missing_blobs` but have no ZIP entry. Their declared hashes and sizes remain manifest metadata.
- A mismatched payload position is `MissingEntry` only if the expected path is absent and the observed path belongs later in the inventory. A swap or other misplaced but still-present entry is `UnexpectedEntry`, as are unlisted and trailing surplus entries.
- §5.3 references an imported-history logical schema not included in the supplied public inputs. For `record_type=imported_history`, the reader validates that the complete file is canonical CBOR containing an array of maps, but does not invent missing per-record field requirements or apply importer/provenance semantics. Unknown record types remain opaque hash-checked record bytes; they never gain authority.
- Canonical objects and blobs stay opaque, byte-exact borrowed slices. No files are created from attacker-selected paths. The entire archive is validated before exposing these slices.
- `export_scope` and `extensions` are canonical-CBOR maps, with arbitrary canonical contents. Noncritical extensions are not interpreted. A nonempty `critical_extensions` array is always rejected.
- The default manifest ceiling is 64 MiB; §3.4 specifies no minimum for this ceiling. Other defaults meet the required ≥1,000,000 entries / 64 GiB per entry / 1 TiB total capacities. Runtime allocations are proportional to physically supplied, checked bytes. The API requires callers to retain the underlying archive bytes for borrowed payloads.
- The root uses the original exact canonical-CBOR inventory byte ranges, not a re-encoding. This is equivalent to canonical encoding because the strict decoder has already established canonicity.
- The source crate has only `sha2` and `crc32fast` dependencies, no dev dependencies or build scripts. The separate, optional `fuzz/` cargo-fuzz crate necessarily declares `libfuzzer-sys`, and is not built by normal `cargo test`.
- No Rust compiler or Cargo executable was available in the authoring environment, so compilation and test execution could not be verified here. Run `cargo test --offline` if dependencies are cached, or `cargo test` in a provisioned environment; `fuzz/` is opt-in.
